# note運用台帳

最終更新: 2026-11-04
状態: 初期設計・無料記事の企画ストック作成段階

## 1. 運用目的

noteを使い、無料記事で読者の関心・悩み・反応を検証する。その結果をもとに有料記事のテーマを選び、記事制作と運用の一部をJ.A.R.V.I.S.へ段階的に移管する。note運用で得た知見とJ.A.R.V.I.S.の能力を、将来的な在宅ワークの検討にも活用する。

短期的な売上だけで判断せず、読者需要・記事品質・継続可能性を分けて評価する。

## 2. 運用方針

1. 初期は無料記事を中心に公開し、需要と反応を確認する。
2. 最初の観察期間は各記事の公開日から30日を基本とする。7日・14日・30日で数値を記録する。
3. 無料記事の反応は有料購入の保証ではない。無料記事の閲覧・反応と、有料記事の購入・売上は別指標として評価する。
4. 最初の無料記事は、異なる読者ニーズを比較できるテーマを選ぶ。
5. 有料記事を始める際は、初期制作をKAREN（ChatGPT）とJ.A.R.V.I.S.の併用で行い、品質・正確性・作業時間を比較する。
6. J.A.R.V.I.S.への移管は、実際の品質と運用安定性を確認して段階的に行う。人間による最終確認は維持する。
7. 記事の医学・薬機・美容施術に関わる説明は、断定や誇張を避け、根拠と個人差を確認する。

## 4. 初期無料記事の候補

現時点の仮候補。公開順は検索需要・競合・本人の経験・記事の独自性を確認して最終決定する。

| 仮テーマ | 検証したい方向 |
|---|---|
| ミルクとオイルの違い | 具体的な商品選び・使い分けの悩み |
| 髪質改善とは何か | 言葉の曖昧さや施術への誤解・疑問 |
| 美容師が実は思っていること | 専門家の視点を読み物として届ける |

この3テーマは「実用」「専門解説」「読み物」の異なる切り口を比較するための候補であり、需要が確認済みという意味ではない。

## 5. 記事ごとの管理項目

記事企画を作成したら、以下を記録する。

- 管理ID
- 仮タイトル／公開タイトル
- カテゴリー
- 対象読者
- 読者が抱える具体的な疑問・悩み
- 記事を読んだ後に得られること
- 独自の経験・根拠・確認が必要な情報
- 無料／有料
- ステータス（ストック／企画中／執筆中／確認中／公開済み／改善／保留）
- 公開日・note URL
- 7日／14日／30日のビュー、スキ、コメント
- 有料の場合は価格、購入数、売上
- 流入経路（取得できる範囲）
- 振り返り・次の改善案

未取得の数値は推測で埋めず「未取得」とする。

## 6. 評価ルール

- 閲覧数が少ない場合、テーマ需要がないと即断しない。露出・タイトル・公開後の日数を分けて見る。
- 閲覧数と反応率を分けて見る。
- 反応が良い無料記事でも、有料化の前に「読者がお金を払ってでも解決したい追加課題」があるか検討する。
- 少数記事の結果から一般化しない。記事数と観測期間を併記する。
- 成功・失敗の判定基準は、初期データを見てから設定する。

## 7. 制作・運用フロー

1. アイデアをストックへ追加
2. 読者・悩み・記事価値を定義
3. 事実確認と構成作成
4. KARENとJ.A.R.V.I.S.で原稿を作成・相互確認（初期の有料記事を含む）
5. 本人が内容・経験・表現を最終確認
6. noteで公開
7. 7日・14日・30日で実績を記録
8. 分析を次の企画へ反映

## 8. J.A.R.V.I.S.への引き継ぎ要件

将来的にJ.A.R.V.I.S.が次を扱えるようにする。

- この台帳を読み、記事ストックと運用方針を把握する
- 新しいアイデアを重複確認して追加する
- 記事企画・構成・草稿を作成する
- 公開済み記事と実績を紐づける
- 期間別の数値を比較し、根拠と限界を明記して分析する
- 次の企画候補を提案する
- KARENなど外部AIへ渡すための最新引き継ぎ要約を生成する
